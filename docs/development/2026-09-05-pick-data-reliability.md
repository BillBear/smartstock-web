# 候选数据链路修复记录

## 范围与结论

分支：`fix/pick-data-reliability`；起点：`836145b8c201fba331cc198e401360e064cb4e4c`。
本轮修复缓存刷新、保存状态和只读展示，不调整评分、排序、模型融合、交易动作、仓位或风控参数。
没有重新生成正式候选、执行模型推理、训练或回测，也没有修改生产数据库结构/记录。
测试使用临时 SQLite 隔离环境，不把其状态解释为运营 PostgreSQL 的状态。

## 已复现问题与修复

1. `get_today_picks` 对非 fallback 来源不检查缓存 TTL，超时结果也可能被当日长期复用。
   所有来源现在遵守已有 TTL；显式刷新接口传入 `force_refresh=True`，只绕过本次身份的结果缓存。
   保留底层行情/市场快照缓存、节流和周末/历史只读规则；不是强制全量外部行情刷新。
2. 候选快照保存异常被静默吞掉。新增 `snapshot_persistence.status=saved/failed`，错误只记录类型，
   不向响应暴露数据库连接信息。保存失败不修改计算出的候选字段，前端不再提示刷新成功。
3. 旧快照缺少顶层超时统计，页面只看市场池覆盖就显示成功。现在同时检查逐只候选的超时状态、
   概率类型和 legacy 策略版本标记；降级数据明确标为代理估计，并区分分析失败与风险闸门。
4. 交易日展示旧快照时误用目标日期/目标日期年龄。现在使用实际 `snapshot_trade_date` 和
   `snapshot_age_days`；年龄未记录时不伪造为零。候选表旁重复显示来源日期和年龄。
5. 未记录的市场因子通过 `Number(value || 0)` 显示零分。现在显示“未记录”，真正的零值仍显示 0.00。
   页面加载时间明确称为“页面读取时间”，不是行情更新时间。候选原始分数、收益数字和顺序保持不变。

## 对抗性检查与限制

- `cached_only` 与关闭交易日不能被 force 绕过；另一个用户/风险缓存不会被清空。
- 同一固定输入在缓存过期重建前后的所有候选字段完全一致；模拟保存失败也不改变候选字段。
- AST 比对确认 CoachService 只有 `get_today_picks` 方法变化，评分/排序/风控方法均未变。
- 此证据证明工程路径与固定输入一致性，不证明策略有效、模型有效或收益改善；未提交策略晋级结论。
- 真实整批分析超时根因尚未闭合；12 秒预算、后台线程、跨源复权/成交量差异仍需独立验证。
- 缓存可刷新不保证外部数据一定新鲜；也不会把 7 月记录改写成 9 月数据。
- 已有 Python LibreSSL/依赖弃用、Vite CJS 弃用告警保留，未通过依赖升级扩大修复范围。
