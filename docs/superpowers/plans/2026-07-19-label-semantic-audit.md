# 标签语义审计计划

## 研究问题

当前全市场资产并存三种十日结果语义：旧 `label_strong_path_10d`、截面 `alpha_top10_10d` 与由固定绝对阈值重建的 `label_actionable_positive_10d`。它们分别回答“收益和路径均严格”“相对市场/行业排序更强”和“绝对收益可交易”。如果把它们替换、混合或用于同一个模型目标而不审计，会造成目标不一致和表面上矛盾的训练结果。

本轮只审计，不修改生产标签、特征、模型或策略。

## 冻结范围

- 仅加载 `fm2_c566fd1c47b64dde7f16` 注册开发期日期；拒绝任何封存时间留出或开发期外日期。
- 样本单位为 `trade_date + symbol`，仅保留已有 `eligible_for_training_10d` 的完整十日结果。
- 旧强势标签、Alpha Top10、绝对可交易标签和三种严重风险标签都从同一原始十日路径字段读取或按既有 `DecisionLabelContract` 重建。
- 此审计可使用未来字段，因为它是标签质量诊断；产物不得进入信号日特征或模型选择。

## 任务

1. 实现不可变开发期加载和标签语义审计器。
   - 输出每日事件率、旧/Alpha/绝对标签的 overlap 矩阵、严重风险一致性、收益/最大浮盈/最大回撤分布、旧强势与 Alpha Top10 不一致的路径原因。
   - 输出按既有市场状态（这是事后结果分层）和股票板块/行业的诊断；明确其不能用于训练期状态选择。
2. 单元测试。
   - 封存或开发期外日期必须被拒绝。
   - Alpha 与路径标签的交集、差集、Jaccard 和原因归属必须可复现。
   - 重建的可交易/严重标签不得重叠，且不得改变输入。
3. CLI 和正式运行。
   - 产物写入 `ml-assets/runs`，包括 `daily_label_distribution.csv`、`label_overlap.json`、`label_disagreement_reasons.json`、`label_semantic_report.json` 和 `progress.json`。
   - 文档记录结果与结论，不提交 Parquet/CSV/JSON 运行产物。

## 验收标准

- 327 个开发期日期完整覆盖，且零封存日期被读取。
- 所有标签率、交并集、每日分布均可由同一输入重现。
- 明确区分“相对收益排序目标”“绝对路径可交易目标”和“风险目标”，不以审计结果直接改标签阈值。
- 如果定义不一致，不宣称某一标签更好；只提出下一轮单一可证伪研究假设。
